# 阶段 7 候补 spike：OCR、语音速记、桌面服务卡片

**状态**：只有评估与实验方案，**没有执行任何一个 spike，也没有 go / no-go 结论**。三项都要在真机上才能证伪：识别质量、系统能力是否存在、卡片能否刷新，用 Node 测试或编译都回答不了。本文的作用是让你拿到 dev 包签名后，每项能在半天内跑完并用同一套判据下结论；下面标为“建议”的判据是我的提议，可以由你调整。

## 1. 图片分享转文字（OCR）

- **要证伪的假设**：对常见中文截图（聊天、网页、笔记、小红书图文），识别结果无需大改就能当草稿用。
- **方法**：dev 包里加一个隐藏入口，用系统相册选择器取图，调用识别，页面上只显示耗时与文字，不保存原图、不落盘、不投递；用 20 张真实中文截图（含深色界面、小字、图文混排、带二维码各若干）逐张记录“可直接使用 / 需小改 / 不可用”与耗时。
- **建议判据**：≥ 17 / 20 可直接使用（改动不超过约 5% 的字符）且平均耗时 ≤ 2 秒 → go；12–16 张 → 只做“识别后可编辑”的辅助入口，不宣传为自动转写；< 12 张 → no-go。
- **产物（go 时）**：`mode: text` 草稿，并标注“由图片识别，请校对”；不保留原图。
- **依赖**：入口取决于阶段 5。分享扩展 go 时，图片从分享面板进来；no-go 时降级为编辑面板里的“从相册识别”，价值明显低于“分享即转写”，做不做要重新评估。
- **成本**：spike 约半天；go 后约 1–1.5 天（入口、错误与超时、测试）。

## 2. 语音速记

- **要证伪的假设**：离线中文识别对 10–30 字的口述短句足够准，且首字延迟可接受。
- **方法**：dev 包里加一个隐藏入口，按住说话、松开出字，只显示文字、耗时与首字延迟；20 句口述（安静与嘈杂环境各一半），统计字准确率。同时验证：权限被拒绝或“不再询问”后的降级路径、通话或录音被占用时的报错、离线模型首次使用是否需要额外下载。
- **建议判据**：字准确率 ≥ 90% 且首字出现 ≤ 1 秒，权限拒绝后仍有明确的可重试提示 → go；否则 no-go。
- **需要你决定的产品问题**：归知手机端目前只有网络与手势检测两项权限（0.7.0 起再加振动），一个只做收集的应用申请麦克风会明显扩大隐私面。即使质量达标，也建议你确认“可以接受申请麦克风”之后才进入实现。
- **成本**：spike 约半天；go 后约 1.5–2 天（权限流程、状态机、编辑器接入、测试）。

## 3. 桌面服务卡片

- **要证伪的假设**：2×2「记一笔」卡片能一次点击直达编辑面板，并显示不过时的“待发送 N 条”。
- **对计划的一处修正**：计划把它标为依赖阶段 5a 的多进程存储。卡片若只显示数字，可以避开多进程写：主应用是唯一写入方，草稿数量变化时用 `updateForm` 主动推送；卡片扩展只在 `onAddForm` 时读一次初始数字。是否成立取决于两点：`updateForm` 能否从主应用的 UIAbility 里调用并生效，以及 `onAddForm` 读取该数字的方式在多进程下是否安全。这两点都要真机验证；若成立，卡片可以不等 5a。
- **方法**：dev 包里加最小卡片：显示固定文案与一个由主应用推送的数字，点击通过 `postCardAction` 拉起主应用的编辑面板。验证：卡片可添加到桌面；冷启动与热启动都能进入编辑面板；主应用里增删草稿后数字何时更新；卡片扩展进程不写草稿存储。
- **建议判据**：能添加、能直达编辑、数字在主应用变化后 10 秒内或下次桌面刷新时正确、不新增权限 → go。
- **成本**：spike 约 0.5–1 天；go 后约 1.5–2 天。

## 建议顺序

1. **OCR**：d.ts 没有标注权限，预计不新增权限（spike 时核对），判据最容易量化，半天就能给出结论；但它的价值取决于阶段 5 的走向，所以最好在 5 的结论出来后再排期。
2. **服务卡片**：修正依赖后不必等 5a，成本可控，价值是缩短“想到 → 记下”的路径。
3. **语音**：技术上最简单，但要先由你决定能否接受麦克风权限，所以放在最后。

这个顺序是我基于成本、依赖与权限面的判断，不是实测结果；真机结论出来后应当重排。

## 暂不做（沿用计划）

小艺意图（成本高）、系统推送（需 AGC 项目且中转要持有推送凭据，扩大机密面）、图片与文件上传协议、手机端阅读与搜索知识库（需端到端加密或直连桌面，属于产品决策）。
