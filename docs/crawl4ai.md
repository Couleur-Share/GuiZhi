# 内置网页采集、文档站与网页研究

状态：Windows x64 本地候选已执行安装与联网验收，分项结果和限制见 [验收记录](crawl4ai-live-validation.md)。按用户要求暂缓其他平台验收；尚未公开发布。

普通公开网页默认使用随包的 Crawl4AI 正文处理和独立 Chromium 渲染。用户不需要安装 Python、pip、Docker 或 Chrome，也不需要选择引擎。视频、字幕、转写、OCR、论坛楼层和已有登录平台继续使用原来的专用连接器。

## 单页采集

桌面粘贴和手机转入的普通网址共用网页入口，一次只读取一个页面。导入状态显示组件准备、加载、正文提取和保存。基础采集不会调用大模型。

不支持的系统或缺少组件时，普通网页可使用旧 Readability 路径，任务保留降级原因。已经遇到的安全拒绝、登录要求、验证码和访问限制不能通过回退绕过。文档站和网页研究需要组件可用。

设置 → 采集与转写 → 内置网页采集显示版本、架构、运行状态和原因。“修复组件”打开当前归知版本的安装包页面，重新安装恢复组件，不会执行在线 pip 更新。组件随归知版本更新。

## 文档站

导入 → 导入文档站，填写入口和目标集合。默认目录是入口页面所在目录，页面会展示完整实际范围；范围限定同源且按目录边界匹配，例如 `/docs/` 不包含 `/docs2/`。

默认最多 50 页、深度 2，最多可设为 300 页、深度 5。一页对应一个知识条目。发现使用持久化的有限队列，循环链接不会无限展开。页面链接和 sitemap 中的候选服从同一范围；robots 明确禁止的路径会跳过，规则读取失败会暂停批次。当前最多读取 3 份同源 sitemap，不递归展开 sitemap 索引。

批次分别统计新增、重复、更新、待采用版本、无变化、失败、跳过和取消。可以暂停、继续、取消和重试失败页。应用重启后，中断队列等待用户继续，不自动重新入库。部分失败仍保留已经完成的条目。

## 原文版本与编辑保护

重复条目默认跳过；选择更新后比较原文哈希。完整新原文与上次相同则只更新检查记录。条目正文仍等于最后采用基线时，先保存本地快照再更新；已经手动编辑或没有可靠历史基线时，只保存待采用版本。

知识详情的“原文版本”支持查看当前正文和所选版本、明确采用。采用前再次检查正文哈希和标题，比较期间发生编辑会拒绝覆盖。标题单独保护；标签、集合、收藏等组织信息保持不变。旧摘要保留并标记需要重新整理，全文检索同步更新，旧向量与 Wiki 摄取关联失效。

失败、截断或不完整正文不能覆盖完整原文。网站删除或拒绝访问也不会删除本地条目。历史条目不会自动重抓，也不会把当前正文推断为从未编辑。

## 指定网页研究

研究来源新增“网页”。最多指定 10 个入口，每个入口默认只读该页，也可以选择目录。快速研究的网页候选总预算为 20 页，深度为 60 页，预算在全部网页入口之间共享；不接入全网搜索。

本轮抓到的正文用于候选排序和精读，避免马上重复下载；相同正文合并并保留来源。网页不使用虚构的互动热度。最多自动精读 6 个候选，报告生成、保存正式知识和关联本地知识仍由用户操作。

纯网页研究默认“不限时间”。混合平台默认近期，手动选择优先。不限时间允许发布日期未知的材料作为证据，不用捕获时间替代发布日期；报告、比较、导出和显示读取保存的时间模式。旧记录默认为近期。研究证据快照保存原始引用、日期置信度、捕获时间和段落位置，后续网页版本更新不会回写旧报告证据。

## 系统、代理与数据

目标基线为 Windows 11+、macOS 14+、Ubuntu 22.04+/Debian 12+。Windows ARM64 应用使用 x64 采集运行包，依赖 Windows 11 仿真，须有真机验收后才能认定支持。

网页请求沿用归知显式代理和系统代理设置。直连逐跳校验并钉扎公网 IP；代理负责远端解析时属于可信出口，不能声称本地已钉扎代理端 DNS。代理失败不会静默直连。浏览器保留沙箱、证书校验，禁止未受控直连、Service Worker、WebSocket 和自动下载。

知识库备份包含批次、已保存正文版本与研究记录。临时浏览器资料和采集缓存不属于备份。升级 schema 后不可直接让旧应用打开新数据库；回退应用需要匹配的升级前备份。

技术实现与当前验收边界见 [实施和验收记录](crawl4ai-implementation.md)。
