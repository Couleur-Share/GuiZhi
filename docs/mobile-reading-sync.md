# 手机阅读与加密同步方案

状态：阶段 2 桌面与独立同步服务已完成本地合成验证，实验入口默认关闭；手机阅读界面和生产部署尚未交付。更新日期：2026-10-08。进度见[实施计划](./mobile-reading-implementation.md)，基础实现见[协议与验证](./mobile-reading-protocol.md)，服务接线见[阶段 2](./mobile-reading-phase2.md)。

用户已接受：由归知托管加密后的知识库副本，使电脑关闭后手机仍可下载并阅读已同步内容。以下首版范围与实现顺序是据此提出的工程方案，不代表全部细节已经确认或验证。

## 1. 产品目标

PC 保留完整本地主库，负责采集、解析、AI 处理和正文整理；手机保存本地阅读副本；云端持续保存加密的同步数据。不开启同步的用户仍可完全本地使用。

首要验收场景：晚上在 PC 整理文章并完成同步，退出归知；第二天手机通过网络下载这些文章，然后开启飞行模式仍能浏览、搜索和阅读。

首版限定一台写入 PC、一台鸿蒙手机。PC 是正文与分类的唯一写入端；手机继续沿用现有收集流程。阅读位置计划仅保存在手机本地，当前阶段 3 尚未持久保存位置。多 PC 写入、手机编辑正文、跨设备批注、云端 AI 和纯手机独立采集处理留待后续设计。

## 3. 首版用户体验

1. PC 设置中开启“手机阅读”，选择知识库，查看拟同步条数及预计大小；默认关闭，不能沿用“手机收集”的同意直接上传历史正文。
2. 通过设备确认建立独立阅读授权，并完成恢复密钥保存流程；显示准备、上传、完成或可重试的失败状态。
3. 手机新增“知识库”入口，下载所选库的标题与正文，支持分类、标签筛选和本地文本搜索。
4. 图片按需下载；“离线保存”下载该文章可同步的图片，逐项报告缺失资源，不能只下载文字就宣称整篇已可离线阅读。
5. PC 关闭后仍可从云端下载此前已同步内容；手机无网络时阅读已下载内容。新提交链接仍等待 PC 上线处理，明确区分“已提交”和“已生成可阅读正文”。

手机显示“最后同步成功时间”“已下载 / 待下载条数”和当前错误；搜索结果说明仅覆盖已下载内容。首次同步、未选择知识库、库内为空、离线缓存和加载失败分别呈现。

同步只在应用允许执行的时机进行，首版以应用前台、手动刷新、PC 数据变更后的队列处理为基础，不承诺鸿蒙后台常驻。

## 4. 数据范围

| 数据 | 首版处理 |
| --- | --- |
| 条目标题、当前可阅读正文、已有摘要、类型与归档状态 | 加密同步；沿用桌面当前阅读内容选择规则，投影实现前核对编辑版、采集版的优先级 |
| 所选知识库名称、标签、条目关系和安全的来源链接 | 加密同步；移动端使用同步专用的不透明 ID |
| 正文引用且 PC 已保存的图片 | 独立加密对象，手机按需缓存；缺失图片展示原因，不自动带登录凭证访问原站 |
| 删除、移出同步范围、取消知识库选择 | 产生撤回记录，手机下次同步移除相关阅读副本及索引；共享图片按引用清理 |
| API Key、Cookie、访问令牌、原始 access_uri、代理口令、配对凭证 | 不进入阅读投影；不上传整库或整个配置目录 |

视频、音频原文件、PDF 原文件、原始网页 HTML 快照、Wiki、研究报告和自定义 AI HTML 阅读页不在首版同步范围；条目已有的可阅读文字可同步。界面应说明这些边界，不能把“知识库已同步”表达为原库所有资源完整可用。

云端不保存正文全文索引或向量。手机落盘内容始终为密文，前台解密后在内存中全文搜索，不持久保存明文索引；导入内容按不可信数据处理，阅读器禁用主动脚本和自动远程资源请求，并校验链接协议。

## 5. 同步与存储设计

采用独立的阅读同步接口与存储空间。可以与收集中转共享部署设施，但路由、凭证作用域、配额、日志和清理任务必须隔离；收件箱的 30 天清理规则不能作用于阅读副本。

云端存储必要的路由和运行元数据，例如不透明库 ID、对象 ID、设备授权、版本、对象大小、上传时间及用量。标题、正文、标签、来源和附件内容应在客户端加密；“云端无法读取正文”不等于“服务端看不到任何元数据”。

PC 生成按条目组织的阅读投影，投影与待发送记录可靠落盘，使用单调序号、库世代和对象版本推进同步；不能只按 updated_at 时间戳推断变更。完整性扫描用于补偿遗漏，具体变更捕获方式在第一阶段确定。

先上传该批次引用的密文对象，再原子发布版本清单。手机校验完整性及版本后，在本地事务中应用条目、关系和删除记录，成功后推进游标。失败批次可重试；重复请求不能重复建条目；下载不完整时保留上一个可用版本。

密文对象不可变，重试复用已生成的对象；加密版本改变时产生新对象。拒绝已知版本回退，并把对象身份、版本与库身份绑定到完整性校验中。具体密码方案必须通过两端互操作验证，不能自行发明加密协议。

旧版本和删除记录的清理依赖设备确认及保留策略。游标过期的手机必须重新取得完整快照，不能跳过删除记录。PC 从旧备份恢复时暂停上传，显式处理库世代和重新发布，防止把旧库误当成最新状态覆盖云端。

同步存储不等于备份：删除会传播，PC 仍应保留独立备份。云端快照与回收窗口用于服务恢复，不默认承诺用户历史版本恢复。

## 6. 密钥、恢复与设备撤销

采用成熟的认证加密与密钥封装方案。内容密钥由可信客户端生成，按库管理；服务端只保存密文及必要的密钥封装，不保存可直接解密正文的密钥。最终算法、格式、设备公钥认证及跨语言库选择在技术验证后确定。

设备配对需把用户确认与设备密钥身份绑定，防止服务端或中间环节替换接收密钥。二维码不携带可长期读取知识库的明文主密钥。既有收集权限不能自动转换为阅读权限。

Windows 密钥由主进程通过系统安全存储保护；鸿蒙使用经验证的平台安全存储能力。不可用时阻止持久开启阅读同步，不允许明文回落。手机数据库、索引和缓存的静态保护也要验证，不能只有凭证进入安全存储。

生成高熵恢复密钥，由用户另行保管，用来恢复内容解密能力。服务端账号或设备授权恢复与内容密钥恢复是两个问题，首个远程试点前必须明确各自的流程。恢复密钥的显示、确认与导出入口属于专门功能，不能混入普通备份、日志或设置导出。

丢失 PC 后，授权服务仍需提供独立撤销设备的途径。仅有手机阅读副本不保证恢复完整 PC 数据，因为首版未同步全部原始资源。所有可信设备及恢复密钥均丢失时，服务运营者无法恢复正文；仍有 PC 主库时可重新创建同步库。

撤销设备后立即拒绝其后续请求，并更新后续内容使用的密钥和有效授权。保留版本重加密及清理策略须在试点前确定。已下载内容、旧密钥或离线设备上的副本无法被远程收回；客户端只能在下次获知撤销后尽力清除缓存，不能承诺远程擦除。

## 7. 成本与操作边界

首版按邀请试点实施，暂不确定价格或承诺无限容量。上线前明确单库容量、单对象大小、设备数、上传/下载速率与请求频率上限，并给出可操作的超额提示。成本按实际存储、出站流量、请求量和备份保留测算。

图片通常比正文占用更多空间，分别显示正文和图片用量；用户可清理手机缓存而不删除 PC 内容。暂停同步、撤销手机、移除某库云端副本是不同操作，必须说明各自对本地和云端数据的影响。

清空云端需明确确认与范围，保留 PC 主库；传播到在线手机的删除与离线缓存残留分别说明。生产保留策略应写明活动对象、失去引用的对象和备份副本各自的清理时限；首个远程试点前确定，不沿用收集服务默认值。

## 8. 开发顺序与完成标准

| 阶段 | 交付 | 通过标准 |
| --- | --- | --- |
| 1：协议与互操作验证 | 合成数据阅读投影、加密封装、测试向量、版本清单；验证鸿蒙与 Node 的密码及安全存储能力 | 双端可互相解密；错误密钥、篡改、错误库身份、版本回退均失败；恢复路径有可执行验证 |
| 2：PC 与隔离同步服务 | 选库、变更捕获、上传队列、密文对象、权限、配额与断点恢复 | 新增、更新、移库、删除可稳定同步；服务重启及请求重放不丢数据；服务存储与日志不出现正文或密钥 |
| 3：鸿蒙阅读闭环 | 本地库、列表、正文、搜索、图片缓存、同步状态 | PC 退出后手机仍可下载；飞行模式阅读已保存内容；失败可重试，缺失图片与未下载正文有明确状态 |
| 4：恢复及受限试点 | 密钥恢复、独立撤销、轮换、容量与保留策略、运维记录 | 真机完成丢设备、重装、PC 恢复旧备份、撤销、存储不足和断网演练后，才开放真实资料同步 |

当前已实现阶段 1 基础、阶段 2 PC 与服务接线及阶段 3 鸿蒙阅读闭环。合成数据验证了 PC 不再参与后的手机客户端下载，以及服务关闭、客户端重建后的离线正文搜索和图片读取；SDK 编译通过，真实设备互操作与飞行模式验收仍待完成。未读取或上传用户真实知识库。当前为有界手动完整快照，自动监听和未变对象跨快照复用尚未提供。
