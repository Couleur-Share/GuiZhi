# 网页采集体积与内存验证（Windows x64）

日期：2026-09-26。范围为本地候选、合成知识库和公开网页；其他平台验收已按用户要求暂缓。未安装到宿主、未使用真实知识库，尚未推送或公开发布。

## 当前实现

普通网页先尝试安全 HTTP 获取；需要动态渲染时使用 Electron 的隔离页面；随包 Crawl4AI/Python 负责 HTML 清洗和 Markdown 提取。安装包不再携带独立 Chromium。Python 依赖中的 Playwright 模块仍存在，但本路径不会启动它的浏览器或 Node 驱动。

最多两个采集页面会话、八个网络请求槽位；同来源限流，Python 提取串行。页面结束后销毁窗口，清理存储、缓存、认证及连接；Python 空闲约 60 秒退出。复用 Electron 仍需动态页面渲染进程，不能理解为动态采集没有额外内存。

## 两项实际驻留修复

1. 阅读功能的五份大型浏览器脚本从主进程入口字符串改为独立资源，实际生成阅读页时读取，不永久缓存。入口由 10,978,893 字节降至约 2,266,000 字节；受控主进程对照减少约 33.9 MiB，安装版历史对照减少约 33–35 MiB。图形编译及真实阅读页渲染通过，最终包资源逐份哈希一致。
2. 采集 Session 的权限回调改为模块级固定函数，避免共享闭包保留最后一页的窗口和请求上下文。13 次采集后的 BrowserWindow 堆对象数从 3 个回到启动基线 2 个，强引用链消失。合成样本的快照 shallow size 仅减少约 12 KiB，不能宣传为十几 MiB 的节省。

堆快照会触发 GC，仅用来确认引用关系。诊断中采集后存在编译代码增长、临时分配和保留的堆容量；这些不能全部认定为泄漏。快照 shallow size、V8 heapUsed 和整进程 USS 是不同指标。

诊断证据：`artifacts/crawl4ai/main-memory-2026-09-26/README.md`、`artifacts/crawl4ai/remaining-memory-2026-09-26/README.md`。

### 测量方法

同一离线 Windows Sandbox、8 GiB 内存、软件图形，按官方旧版→候选→候选→官方旧版执行。每轮真实安装器部署并使用全新空白知识库：静态 1 页、动态双页、连续 5 批双页，共 13 次采集。

使用 psutil 每 250 ms 采样归知整棵进程树的 USS，即独占物理内存，排除测试驱动和采样器。空闲取阶段中位数，峰值取最大样本。静态、动态和连续批次后均等待正常空闲回收，再取 8 秒样本；不强制 GC、不修剪工作集。

短命进程退出附近的 AccessDenied 样本保留原始记录并明确排除，不当作低内存样本。每轮总缺失比例必须低于 1%，每阶段低于 10%；三个回收阶段末尾均不得残留 Python、独立 Chrome 或 Playwright Node。宿主审计额外断言四轮对应的 13 份 Markdown 哈希全部一致。

两包显示版本同为 0.24.0，但源码功能和数据库结构不同，所以这是用户实际会得到的整包对照，不能把全部差额归因于采集引擎。受控 13 页、两轮重复及 250 ms 采样不能代替多小时压力测试或捕获所有瞬时峰值。

## 复现入口

`scripts/crawl4ai-acceptance/build-kit.py --guest-script memory-guest.ps1` 生成只读输入、可写输出的离线验收包；运行包中的 `launch.ps1` 启动 Windows Sandbox。来宾脚本只允许在沙盒运行，不能在日常宿主直接执行。完成后用 `report-memory.py --run-root <来宾结果目录>` 汇总原始采样，再核对 13 份正文哈希与输入安装器 SHA-256。

`capture-heap-profile.mjs` 用于临时合成知识库的引用诊断；它在普通采样结束后才生成快照。该入口不是正式内存基准，不能用快照触发的 GC 改善正式结果。
