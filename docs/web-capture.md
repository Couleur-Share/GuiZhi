# 网页采集、文档站与网页研究

普通公开网页先尝试静态获取，有动态内容迹象时复用 Electron 的隔离页面渲染，再由主进程旁的 Node 线程用 Readability 提取正文并转换为 Markdown。用户不需要安装 Python、Docker 或浏览器，也不需要选择引擎。视频、字幕、转写、OCR、论坛楼层和已有登录平台继续使用原来的专用连接器。

2026-11-07 起不再随包分发 Crawl4AI（Python 运行包 193.7 MiB、8,099 个文件），设置里的「内置网页采集」状态与修复入口一并移除。去留评估、两套样本的回归数据和移除清单见 [Crawl4AI 评估与移除记录](agents/crawl4ai-evaluation.md)；`crawl4ai-*.md` 几份实施与验收记录只作历史参考。

## 采集流程

网页采集最多两页并发，共用最多八个安全网络请求槽位。最多复用两个内存页面会话，每页结束清理存储、缓存与认证状态。静态分流使用保守的 HTML 结构判断，不能保证识别所有网站的延迟更新。静态请求、robots.txt 与 sitemap 的请求和渲染窗口使用同一个请求身份（Chromium 自带的 User-Agent，含 `GuiZhi/<版本>` 标记，自报家门，不冒充搜索引擎）；这只是避免“不带 User-Agent 就被直接拒绝”（例如 Wikipedia），遇到 403/429 仍保持失败状态，不回退到渲染窗口重试。渲染窗口里的图片请求不出网，以 1×1 透明图本地应答：正文来自渲染后的页面结构，图片只以网址出现，渲染窗口也不截图。虚拟代码编辑器读取完整文档模型，不能确认完整性时返回可重试失败。

## 正文提取

提取在独立的 worker 线程里串行进行，单页 45 秒超时，输入和输出各 16 MiB 上限，堆上限 1 GiB，空闲 60 秒后线程退出，下次采集约 0.1 秒重新启动。线程内禁用全部网络 API，解析页面不会发出任何请求。

- **代码**：所有 `<pre>` 输出为围栏代码块，内容不转义；语言取自 `language-*`、`lang-*`、`highlight-source-*`、`brush:` 等 class 与 `data-lang`。渲染快照里逐行的 CodeMirror 编辑器拼回代码块。
- **表格**：数据表输出为 GFM 管道表格，合并单元格按网格展开，`|` 转义，表题保留；只用于排版的表格按段落输出。
- **链接与图片**：按最终网址解析为绝对地址；只保留 http(s)、mailto、tel 链接和 http(s) 图片（含 `data-src`、`srcset` 等懒加载写法），其余移除。
- **标题与导语**：保留 h1；正文开头的标题区被当作页框删掉时补回 h1 与导语。标签页面板和 `<details>` 里的内容一并展开（各标签之间没有标签名）。
- **语义区域回退**：Readability 取到的段落文字不足语义区域的 60%、且该区域段落文字至少 500 字时，改用清理后的语义区域（先按 `entry-content`、`post-content`、`article-content`、`post-body` 等内容类名与 `itemprop=articleBody` 匹配，其次 `main`、`article`、`[role=main]`）。比例只统计表格之外 `<p>` 里的文字，章节目录、菜单和大表格不左右判断。回归样本里截断页的比例都不高于 0.52，正常页不低于 0.85。
- **极短页面**：Readability 取到的正文不足 100 字时（它找不到达标正文会退回整页，并去掉 class），改用按上一条规则清理掉导航、页眉页脚和边栏之后的整页。
- **结果与错误**：401、407 与登录页记为需要登录；403、429 记为访问受限；其余 4xx/5xx 记为可重试的网络失败；验证码页与空正文分别报告。正文超过 200,000 个字符时截断并给出警告。微信公众号的单条导入走 `wechat-html/1` 专用路径；经网页采集到达的公众号页面由本提取器直接取 `#js_content`。

每个原文版本记录 `engineVersion`：本提取器为 `readability/1-<路由>`，路由是 `static`、`electron`、`verified-electron` 或 `flaresolverr`。规则或依赖升级使同一页面的输出变化时，提升 `readability/<版本>`，让「检查更新」走下文的引擎变化保护。

已知差异：MDN 浏览器兼容表在走 Readability 的页面里只剩表格结构，走区域回退的页面保留数据；shadow DOM 里的 CodeMirror 只能拿到已渲染的行，长代码可能不全；Python asyncio 模块索引这类索引页会截掉部分条目。

## 单页采集

桌面粘贴和手机转入的普通网址共用网页入口，一次只读取一个页面。导入状态显示准备、加载、正文提取和保存。基础采集不会调用大模型。已经遇到的安全拒绝、登录要求、验证码和访问限制不会通过回退绕过。

## 文档站

导入 → 导入文档站，填写入口和目标集合。默认目录是入口页面所在目录，页面会展示完整实际范围；范围限定同源且按目录边界匹配，例如 `/docs/` 不包含 `/docs2/`。

默认最多 50 页、深度 2，最多可设为 300 页、深度 5。一页对应一个知识条目。发现使用持久化的有限队列，循环链接不会无限展开。页面链接和 sitemap 中的候选服从同一范围；robots 明确禁止的路径会跳过，规则读取失败会暂停批次。当前最多读取 3 份同源 sitemap，不递归展开 sitemap 索引。

批次分别统计新增、重复、更新、待采用版本、无变化、失败、跳过和取消。可以暂停、继续、取消和重试失败页。应用重启后，中断队列等待用户继续，不自动重新入库。部分失败仍保留已经完成的条目。

## 原文版本与编辑保护

重复条目默认跳过；选择更新后比较原文哈希。完整新原文与上次相同则只更新检查记录。条目正文仍等于最后采用的基线、且本次与基线版本的 `engineVersion` 相同时，先保存本地快照再更新；已经手动编辑、没有可靠历史基线，或 `engineVersion` 与基线版本不同时，只保存待采用版本，正文、全文检索、向量与 Wiki 摄取都不动。

换提取器（例如从 Crawl4AI 换成 Readability）后，同一页面的 Markdown 通常整体不同，并不代表原文更新，所以由用户比较后决定。比较对象是当前正文所依据的基线版本，不是最近一次抓取：第一次重采留下待采用版本后，再次重采同样只留待采用版本，不会绕过它直接改写正文。`engineVersion` 包含路由后缀，同一提取器下静态获取与渲染之间切换也按引擎不同处理。

采用只能逐条进行：在知识详情的“原文版本”里查看当前正文和所选版本、明确采用，没有批量采用入口。文档站批次的「待采用版本」计数提示还有多少条目需要逐条处理。采用前再次检查正文哈希和标题，比较期间发生编辑会拒绝覆盖。标题单独保护；标签、集合、收藏等组织信息保持不变。旧摘要保留并标记需要重新整理，全文检索同步更新，旧向量与 Wiki 摄取关联失效。

失败、截断或不完整正文不能覆盖完整原文。网站删除或拒绝访问也不会删除本地条目。历史条目不会自动重抓，也不会把当前正文推断为从未编辑。

## 指定网页研究

研究来源新增“网页”。最多指定 10 个入口，每个入口默认只读该页，也可以选择目录。快速研究的网页候选总预算为 20 页，深度为 60 页，预算在全部网页入口之间共享；不接入全网搜索。

本轮抓到的正文用于候选排序和精读，避免马上重复下载；相同正文合并并保留来源。网页不使用虚构的互动热度。最多自动精读 6 个候选，报告生成、保存正式知识和关联本地知识仍由用户操作。

纯网页研究默认“不限时间”。混合平台默认近期，手动选择优先。不限时间允许发布日期未知的材料作为证据，不用捕获时间替代发布日期；报告、比较、导出和显示读取保存的时间模式。旧记录默认为近期。研究证据快照保存原始引用、日期置信度、捕获时间和段落位置，后续网页版本更新不会回写旧报告证据。

## 代理与数据

网页请求沿用归知显式代理和系统代理设置。直连逐跳校验并钉扎公网 IP；代理负责远端解析时属于可信出口，不能声称本地已钉扎代理端 DNS。代理失败不会静默直连。浏览器保留沙箱、证书校验，禁止未受控直连、WebSocket 和自动下载；响应附加 worker-src CSP 禁止 Service Worker 及其他网页 Worker。

知识库备份包含批次、已保存正文版本与研究记录。临时浏览器资料不属于备份。升级 schema 后不可直接让旧应用打开新数据库；回退应用需要匹配的升级前备份。
